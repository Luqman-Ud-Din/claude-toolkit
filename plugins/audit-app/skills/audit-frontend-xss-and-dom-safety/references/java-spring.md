# Java / Spring reference for audit-frontend-xss-and-dom-safety

XSS is mostly a client topic; this file covers the Spring side: server-rendered
templates (Thymeleaf, JSP, FreeMarker, Velocity), HTML-returning endpoints,
and server-side sanitization a frontend bypass may rely on.

## Stack markers
`pom.xml`/`build.gradle` with `spring-boot-starter-thymeleaf`, `spring-boot-starter-freemarker`, `spring-boot-starter-web` plus `src/main/webapp/**/*.jsp`, `src/main/resources/templates/**`, `src/main/resources/static/**`.

## Where the relevant code lives
`templates/**/*.html` (Thymeleaf), `**/*.jsp|jspx|tag`, `templates/**/*.ftl|ftlh`, `**/*.vm`, `static/js/**` (raw DOM code), `@Controller` methods returning `String` bodies with `produces = "text/html"`, `@ResponseBody` HTML, error handlers (`@ControllerAdvice` building HTML), email builders, `org.owasp.html.PolicyFactory` / `Jsoup.clean` (server-side sanitizers).

## Dangerous / interesting APIs and patterns
- Bypasses (BYPASS/SSR): Thymeleaf `th:utext` (unescaped), `[(${...})]` inline unescaped expression, `th:href="${user}"` (encoded but scheme unchecked), `th:onclick`/`th:on*` with expressions (JS context), `th:inline="javascript"` with `[(...)]`, `th:attr="innerHTML=..."`; JSP `<%= x %>` scriptlets, `${x}` in JSP without `escapeXml` (JSP EL does **not** escape by default - `<c:out>` does), `fn:escapeXml` missing; FreeMarker `${x?no_esc}`, `<#noautoesc>`, `auto_escaping_policy` disabled, `.ftl` (legacy, no autoescape) vs `.ftlh`; Velocity (no autoescape unless `EscapeHtmlReference` configured); `MessageSource` messages rendered unescaped with user args.
- HTML built in Java: `"<div>" + x + "</div>"`, `StringBuilder.append("<")`, `HtmlUtils.htmlEscape` missing; `ResponseEntity.ok().contentType(TEXT_HTML).body(str)`; `response.getWriter().write("<html>" + x)`.
- Script context: `<script>var d = /*[[${data}]]*/ {};</script>` - Thymeleaf JS inlining escapes correctly; hand-built `<script>var d = ` + `objectMapper.writeValueAsString(x)` does not (`</script>` breakout).
- Static JS (`static/js/**`): `innerHTML =`, `document.write(`, `$(...).html(`, `eval(`, `location.href = ` from query params.
- SRI/INLINE: layout templates with `<script src="https://cdn...">` without `integrity`; inline `<script>` and `onclick=` handlers; `webjars` are same-origin (no SRI needed).
- Sanitizers: OWASP Java HTML Sanitizer (`Sanitizers.FORMATTING.and(Sanitizers.LINKS).sanitize(x)`), `Jsoup.clean(x, Safelist.basic())`, `HtmlUtils.htmlEscape` (escaper, not sanitizer). A frontend "the API sanitizes" claim is justified only if one runs on the **write** path for that field.

## What "good" looks like
```html
<!-- Thymeleaf escapes by default -->
<p th:text="${comment.body}"></p>
<!-- Justified unescaped output: value sanitized by OWASP sanitizer in HelpService (see ADR-12) -->
<div th:utext="${article.safeHtml}"></div>
<!-- Data into JS: use inlining, not string concat -->
<script th:inline="javascript">var cfg = /*[[${cfg}]]*/ {};</script>
<!-- Third-party script -->
<script src="https://cdn.example.com/lib.js" integrity="sha384-..." crossorigin="anonymous"></script>
```
```java
PolicyFactory policy = Sanitizers.FORMATTING.and(Sanitizers.LINKS).and(Sanitizers.TABLES);
entity.setDescription(policy.sanitize(dto.getDescription()));   // on write
```

## Manual trace checklist
1. Every `th:utext`, `[( )]`, `?no_esc`, `<%= %>`, `${}` in JSP: model attribute source.
2. `th:href`/`th:src`/`th:action` bound to user data - scheme check present?
3. Layout/fragment templates: third-party scripts (SRI), inline scripts and `on*` attributes (CSP).
4. Controllers producing `text/html` from strings; custom error pages echoing request data (`ErrorController` with `request.getRequestURI()`).
5. If the SPA relies on API sanitization: find `Sanitizers`/`Jsoup.clean` on the write path.
6. Email templates with user fields (HTML injection -> phishing, Medium).

## Stack-specific false positives
- `th:utext="#{message.key}"` with resource-bundle messages only developers edit - Info.
- `th:utext` on markup generated by the app (pagination) with no user data - Info.
- `[[${x}]]` (double bracket) is escaped; only `[(${x})]` is unescaped.
- `.ftlh` templates auto-escape; `?no_esc` on constants.
- `eval` in vendored `static/js/lib/**`.

## Tooling
- `spotbugs` + `findsecbugs` (XSS_REQUEST_PARAMETER_TO_SERVLET_WRITER, XSS_JSP_PRINT, JSP_JSTL_OUT missing escapeXml).
- `semgrep --config p/java --config r/java.spring.security.injection` (`thymeleaf-utext`, `jsp-scriptlet`).
- `$AUDIT_CORE_ROOT/skills/audit-code-scan/scripts/grep_scan.py` with `scripts/patterns/java-spring.json`; `scan_html_scripts.py` over `templates/**`, `webapp/**`, `static/**`.
