# Python / Django reference for audit-dependency-vulnerabilities

## Stack markers
`requirements.txt` (and `requirements/*.txt`, `requirements-dev.txt`),
`pyproject.toml` (`[project.dependencies]`, Poetry `[tool.poetry.dependencies]`),
`Pipfile` + `Pipfile.lock`, `poetry.lock`, `uv.lock`, `setup.py`/`setup.cfg`,
`manage.py` (Django). Variants: Flask/FastAPI use the same files - the generic
sections apply; Django adds the LTS-line question.

## Where the relevant code lives
- Direct deps: the requirements/pyproject file. Resolved graph: the lockfile if
  any; otherwise `pip freeze` in the deployed environment (not available in a
  read-only audit - say so).
- Constraints: `-c constraints.txt`, `[tool.pip-tools]`, Poetry `[tool.poetry.group.*]`.
- Index config: `pip.conf` / `pip.ini`, `--index-url` / `--extra-index-url` lines,
  `PIP_INDEX_URL` in Dockerfiles and CI.
- Runtime: `Dockerfile` `FROM python:3.x-slim`, `runtime.txt`, `.python-version`.

## Dangerous / interesting APIs and patterns
- Famous vulnerable versions: Django 3.2 < 3.2.25 and every EOL line (1.x, 2.x,
  3.0, 3.1, 4.0, 4.1), Django 4.2 < 4.2.11 / 5.0 < 5.0.3 (CVE-2024-24680, 27351),
  `requests` < 2.32.0, `urllib3` < 1.26.18 / 2.0.7, `PyYAML` < 5.4, `Pillow` < 10.3.0,
  `cryptography` < 42, `Jinja2` < 3.1.4, `Werkzeug` < 3.0.3, `gunicorn` < 22.0
  (request smuggling), `sqlparse` < 0.5.0, `djangorestframework` < 3.15.2 (XSS),
  `celery` < 5.2.2, `lxml` < 4.9.1, `setuptools` < 70.
- Unpinned lines in production requirements (no `==`), `>=` only, VCS URLs
  (`git+https://...` without `@<sha>`), `--extra-index-url http://`, `--trusted-host`.
- `pip install` in Dockerfile without a lock/hash mode (`--require-hashes`).
- Django `SECURITY WARNING`-style middlewares are not dependency issues - leave to
  `audit-security-headers-and-middleware`.

## What "good" looks like
```text
# requirements.txt (generated by pip-compile --generate-hashes)
Django==4.2.16 \
    --hash=sha256:...
requests==2.32.3 \
    --hash=sha256:...
```
CI: `pip-audit -r requirements.txt --strict` (non-zero exit on any advisory) and
Dependabot `pip` ecosystem; Dockerfile `pip install --require-hashes -r requirements.txt`.

## Manual trace checklist
1. Django line: is it a supported LTS/current line? An EOL Django is one High
   finding that subsumes every framework CVE since the EOL date; name the target
   LTS and link the release notes for the jump (breaking: yes).
2. For each pip-audit row: pip-audit gives no severity; open the CVE (aliases) and
   take the CVSS band, then check reachability (Pillow only matters if images are
   decoded from users; PyYAML only if `yaml.load` on untrusted input).
3. Transitives: `pipdeptree -r -p <pkg>` (needs an installed env); otherwise
   reason from the lockfile. Fix via parent bump or a constraints file.
4. Verify pins: a `requirements.txt` with `>=` means the deployed version is
   unknown - the audit result is for the lower bound only; say so in Not checked.
5. Runtime: python base image tag (3.8 EOL Oct 2024; 3.9 EOL Oct 2025).

## Stack-specific false positives
- pip-audit resolves `requirements.txt` in a temp env; if resolution fails on a
  private package it reports nothing for that file - that is *not checked*.
- Dev-only tools (`black`, `pytest`, `coverage`) with advisories: Low.
- Advisories on `pip`/`setuptools` themselves inside the base image are image
  findings (trivy), not app-manifest findings.
- Django "vulnerable" per KB but the project pins a backported distro package
  (Debian `python3-django`) - check the actual installed version.

## Tooling
- `pip-audit -r requirements.txt --format json` (`--desc on` for descriptions)
- `pip-audit --format json` inside the venv (covers installed transitives)
- `pipenv check --output json`, `poetry audit` (plugin), `safety check --json` (commercial DB)
- `osv-scanner --lockfile requirements.txt`, `trivy fs .` (reads `poetry.lock`, `Pipfile.lock`, `requirements.txt`)
- `pip list --outdated`, `pip index versions <pkg>` for last release
- `pip-compile --generate-hashes` to produce pinned, hashed requirements
